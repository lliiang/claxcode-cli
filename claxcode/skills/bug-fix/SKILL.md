# Bug Fix

## Description

缺陷修复方法论：先复现、找根因、最小修复、回归防复发。不猜原因，不修表象。

## Instructions

修复 bug 时严格按以下顺序：

**1. 复现（一切的前提）**
- 先让 bug 可重复出现：运行失败测试、最小复现脚本，或按用户描述重走一遍。
- 无法复现时，先向用户索要复现步骤/日志，不要直接开改。

**2. 定位根因**
- 从错误信息/堆栈出发，读相关代码；怀疑多处时逐一带假设验证（加打印或写小测试）。
- 区分"出错的位置"和"出错的原因"——异常抛出点往往不是根因。
- 若与近期改动有关，优先检查那些改动。

**3. 最小修复**
- 只修根因，用最少的改动；不顺手清理周边代码、不改变无关行为。
- 修复方案有多个时，选最简单、对现有逻辑侵入最小的那个。

**4. 回归验证（缺一不可）**
- 先证明修复有效：复现步骤不再出错。
- 再证明没有破坏：跑相关测试；最好补一个针对该 bug 的回归测试，防止复发。

**5. 汇报**
- 一句话说清根因、修复方式、验证证据；若只缓解了表象，必须明说。

## Commands

- `fix`: 按此方法论修复一个 bug（用法：/fix <bug 描述或错误信息>）
