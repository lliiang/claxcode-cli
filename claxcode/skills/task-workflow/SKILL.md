# Task Workflow

## Description

通用任务处理方法论：接到任务时按"分类 → 探索 → 计划 → 小步执行 → 验证 → 汇报"的流程工作，避免臆测和返工。

## Instructions

处理任何任务时，先判断类型，再按对应流程执行：

**1. 任务分类（先做）**
- 问答/探索：只需读懂代码 → 直接用搜索和读取工具回答，不改文件。
- 修改/新功能：需要动代码 → 走完整流程。
- 调试：复现优先（见 bug-fix 方法论）。

**2. 探索先行（修改前必做）**
- 用 glob/grep 定位相关文件，用 read 读懂现状；绝不猜测路径、函数签名或已有实现。
- 找不到时换关键词再搜，而不是编造。

**3. 计划（超过 3 步的任务必做）**
- 用编号列出步骤，每步可独立验证；先易后难，先根因后表象。
- 计划内只包含任务要求的事，不顺带重构、不扩大范围。

**4. 小步执行**
- 一次改一个步骤，改完立刻验证（读回文件/跑相关测试），再进行下一步。
- 写代码遵循项目已有风格和编码规范：最少代码、最简单实现、扁平不嵌套。

**5. 验证（汇报前必做）**
- 有测试跑测试；没测试至少读回改动确认。
- 验证失败就继续修，不要说"应该没问题"。

**6. 汇报**
- 说清改了哪些文件、验证结果是什么；没验证的部分明确标注"未验证"。

## Commands

- `task`: 按完整方法论处理一个任务（用法：/task <任务描述>）
- `plan`: 只输出执行计划，不动手修改（用法：/plan <任务描述>）
