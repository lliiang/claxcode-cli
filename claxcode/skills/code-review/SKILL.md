# Code Review

## Description

代码审查方法论：按"正确性 > 安全 > 简洁 > 规范"的优先级审查，输出按严重度分级、可直接执行的结论。

## Instructions

审查代码（diff、文件或目录）时按以下顺序检查，发现即记录：

**1. 正确性（最高优先级）**
- 逻辑错误、边界条件（空值/越界/并发）、异常路径、资源泄漏（连接/文件未关闭）。
- 行为是否与注释、文档、测试描述一致。

**2. 安全**
- 注入风险（命令/SQL/路径穿越）、密钥硬编码、敏感信息进日志、不安全的反序列化。
- 写操作是否有权限校验和备份/回滚手段。

**3. 简洁**
- 死代码、重复代码、可以压平的嵌套、过度设计（为用不到的需求做的抽象和配置）。

**4. 规范（最低优先级）**
- 命名、类型标注、docstring、与周边代码风格一致性；lint/类型检查是否引入新违规。

**输出格式（严格遵守）**
- 先给一行总体结论（可合并/需修改/不可合并）。
- 问题按三级分类列出，每条注明 `文件:行号`、问题、建议改法：
  - 🔴 阻断：必须修复（正确性/安全问题）
  - 🟡 建议：应该修复（简洁/明显改进）
  - ⚪ 可选：风格偏好，可不改
- 没有问题就直说"未发现问题"，不要硬凑。

## Commands

- `review`: 审查指定文件、目录或当前改动（用法：/review [路径]；无参数时审查 git 未提交改动）
